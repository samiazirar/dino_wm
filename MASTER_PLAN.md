## Goal

Build and validate a frozen-encoder DINO-WM pipeline that trains, resumes, evaluates open-loop prediction, and runs MPC+CEM planning for PushT, Wall, Rope, and Granular. PushT remains the primary environment; Rope and Granular test the depth-differential hypothesis, and Wall is a flat-scene corroboration control. The locked inferential matrix is `3 arms x 4 environments x 3 paired seeds = 36 cells`: DINOv2, DINOcular, and `dinocular-zerodepth`. Completion means all P0 through P5 execution gates pass for all 36 cells and P6 emits a reproducible evidence bundle. The public DFormerv2 arm remains an engineering stand-in and cheap-control source, not an inferential matrix arm. The DINOcular versus `dinocular-zerodepth` estimand is the effect of informative depth input under fixed encoder weights, not a causal effect of depth-aware pretraining.

### DINO-WM datasets

Repository and paper audit at DINO-WM commit `0a9492fa12044b852ae9e001cc74604b79c8bb0c` finds five supported study environments. `deformable_env` is the common registered wrapper for Rope and Granular, not a sixth task; a dormant `cloth` branch has no README dataset root, task config, or paper evaluation and is not counted.

### Fixed depth producer and cache contract

- Selection audit, verified online and by unauthenticated downloads on 2026-07-14: choose public, ungated `depth-anything/DA3NESTED-GIANT-LARGE-1.1`, the refreshed 1.40B and largest current official Depth Anything 3 release under CC BY-NC 4.0. It provides joint sequence-consistent any-view/video geometry, pose, and metric depth plus the official long-sequence DA3-Streaming mode. It is not gated, so no size downgrade is required. Public, ungated Video Depth Anything Large is explicitly temporal but smaller at 381.8M parameters; public Depth Anything V2 Large is frame-wise. The requested ordering therefore selects DA3, not either fallback and never a Small producer.
- Producer code: `https://github.com/ByteDance-Seed/Depth-Anything-3.git` at commit `e74fd796e96b7e781a5506fd8503b6bd7232513c`, including the official `da3_streaming/` implementation and its `salad` submodule gitlink `6aede13a3f6c25750bf7fde10209c06cb73060bb`. Main weight URL: `https://huggingface.co/depth-anything/DA3NESTED-GIANT-LARGE-1.1/resolve/b2359bdf726fb44ef62acca04d629dcf158053e7/model.safetensors`, 6,759,558,100 B, SHA-256 `8ebe871a022ed58d2fc8fdfb2ebdb31d57b60fe39611c849095851a7b7c6020c`; HF revision metadata reports `gated=false` and `private=false`. Its pinned `config.json` is 3,113 B, SHA-256 `09adf89474017e717bc05aa86fd3a378708ba8914b036d61874eced328069468`. Official loop closure also requires `https://github.com/serizba/salad/releases/download/v1.0.0/dino_salad.ckpt`, 352,040,378 B, SHA-256 `6b3f1720954293e83da6966c5cfcfc6713200d7fefadcca76fc51aeb80b3cada`.
- Treat each official model episode as one complete ordered video trajectory. Decode every selected source frame in order with no temporal subsampling and invoke DA3-Streaming once for that trajectory, never once per frame and never with frames from two trajectories. For Wall, “selected” is the official action-aligned indices `0..49`; the 51st PTH entry is the post-action terminal observation that `WallDataset` never exposes. Use the official defaults: BF16 on Marvin A100, `process_res=504`, `upper_bound_resize`, `ref_view_strategy=saddle_balanced`, loop closure enabled, 120-frame chunks, and 60-frame overlap. A trajectory of at most 120 frames is one joint call; a longer trajectory uses the same 120/60 sliding sequence. The official protocol uses the overlap for dense confidence-weighted Sim(3) alignment and emits each frame once by discarding the duplicated overlap tail; it does not average or blend duplicate depth pixels. Record every chunk boundary and alignment result in the trajectory manifest.
- DA3 resizes the full decoded RGB frame aspect-preservingly to a longest side of 504 and rounds dimensions to multiples of 14. Map each returned metric-depth map back to the decoded frame geometry by the recorded resize factors, then apply exactly the world-model RGB Resize-short-edge 224 plus CenterCrop(224) to both modalities. Use bilinear depth resizing with fixed `align_corners=False`; preserve chronological order and float32 meters until normalization.
- The checkpoint input contract wins over a blanket calibration recipe. Every encoder manifest must state exact RGB channel order and normalization, depth producer and checkpoint, depth units and valid range, invalid-depth value and mask, resize interpolation and `align_corners`, clipping, inversion, and the post-normalization neutral depth value. For the public stand-in, fit `lo_env,hi_env` only on training trajectories selected by the 128 smallest SHA-256 frame keys over `env/train/episode/frame`. From cropped raw metric maps take `d[::8,::8]`; use the combined 2nd/98th percentiles, require finite `hi_env > lo_env + 1e-6`, and store `gray=clip((depth_m-lo_env)/(hi_env-lo_env),0,1)` without inversion. For the real student, first reproduce its native contract. If it expects normalized relative depth, fit one fixed environment calibration on training trajectories only and freeze it across seeds and evaluation. If it expects metric or sensor-range depth, preserve that scale. P2a may select the producer, but both candidates must be converted into the same recovered checkpoint-native input contract. Report clipping, saturation, invalid, and masked-pixel rates for every producer and environment. Never fit calibration on validation or planning targets or per frame, chunk, or trajectory.
- Keep the LMDB wire format fixed but namespace it by producer and input contract: `$STUDY_ROOT/data/depth_cache/<producer>/<contract_id>/<env>.lmdb`, physical key `<split>/<episode:05d>/<frame:06d>`, value zstd-level-3 compressed little-endian float16 `[224,224]`. The construction and recovery unit is the trajectory key `<split>/<episode:05d>`: write all of its frames atomically, never mix trajectory batches, and index its source-video SHA-256, ordered frame count, first-emission context, chunk boundaries, and ordered output keys in `manifest.json`. The manifest also records calibration training keys, native units/range, invalid convention, clipping and saturation counts, every source/code/config/weight hash, dtype, shape, compressor, and final closed `data.mdb` SHA-256. Use sparse `map_size=1 TiB`; actual bytes remain **UNKNOWN** until P0.
- The stock DFormerv2 adapter converts cached gray to `(gray-0.48)/0.28` and adds one channel. DINOv2 ignores depth. A stateful producer cache must use causal first-emission semantics: append observations in order, commit each frame when it is first emitted, and reuse that tensor offline and on every later MPC replan. ## Decision rules

**Encoder/system claim, DINOcular versus DINOv2.** PushT remains the sole formal primary domain. Call DINOcular useful on PushT only if it (a) has a planning-success point estimate at least `0.10` absolute higher, with the crossed paired-bootstrap 95% lower bound above zero, (b) has a positive planning-success delta in each of seeds 1, 2, and 3, (c) has lower pooled NRE point estimates at both horizons 5 and 10 with nondegenerate reported denominators, (d) has a Wall planning-success 95% lower bound above `-0.05`, and (e) passes the arm-blind convergence gate for every PushT and Wall cell in the contrast. The `0.10` threshold is a point-estimate minimum effect, not a requirement that the interval clear `0.10`; the NRE conditions are supporting point-estimate gates, not separate significance tests. Planning is the primary cross-encoder yardstick because NRE is only weakly comparable across latent spaces. Otherwise state that the system did not meet the preregistered utility criterion. Because PushT has almost no intrinsic depth and DINOcular uses 49 tokens versus DINOv2's 196, non-improvement bounds only this complete system under this protocol. It does not falsify depth-aware pretraining or geometry. A positive result also remains system-level because multiple encoder properties differ. Always present the Rope and Granular perspective-domain observations beside the PushT conclusion.

**Informative-depth input test, DINOcular versus `dinocular-zerodepth`.** This identical-checkpoint contrast estimates the effect of informative depth input under fixed weights. It is not a causal test of depth-aware pretraining. For PushT and Wall, define `Delta_success_env = success_depth - success_neutral`; an environment meets its secondary utility rule only if the point estimate and every per-seed delta are positive and the crossed paired-bootstrap 95% lower bound is above zero. Horizon-1 pooled NRE and terminal state error remain within-environment supporting endpoints. For Rope and Granular, report Chamfer Distance and horizon-1 pooled NRE separately as exploratory within-environment support. If and only if P1 recovers both pre-existing deformable binary success criteria before model evaluation, also report their absolute success differences and the exploratory contrast `C_depth=(Delta_success_rope+Delta_success_granular)/2-Delta_success_pusht`, requiring a 95% lower bound above zero and positive perspective-domain point estimates in every seed. State that success criteria differ by environment. If either criterion is absent, omit `C_depth` and make no cross-environment depth-differential claim. Never combine terminal state error with Chamfer Distance or compare their relative ratios across environments. With 10 deformable targets and only three training seeds, do not claim population-level seed coverage.
